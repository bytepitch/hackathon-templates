# hackathon-liveview-starter

A fullstack [Phoenix](https://www.phoenixframework.org) app with [LiveView](https://phoenix-live-view.hexdocs.pm), Postgres and a few basics:

- Elixir 1.20.4 and Erlang/OTP 29.1.2, pinned in `.tool-versions`
- Runs on port 4000 and listens on all network interfaces
- One example resource (`items`) with LiveView CRUD, a context, a migration and tests
- `GET /api/health` returns `{"status": "ok"}`
- `AGENTS.md` generated by Phoenix 1.8
- A `Dockerfile` and a `docker-compose.yml` with Phoenix and Postgres

The official Phoenix and Elixir documentation is pretty good, so this README is short on purpose.
See [phoenix/README.md](../README.md) for prerequisites, sharing the app on the local network, ngrok and the full list of documentation links.

## Run

The quickest way is to start everything in Docker:

```bash
docker compose up
```

Then open:

- http://localhost:4000 for the home page
- http://localhost:4000/items for the example CRUD
- http://localhost:4000/api/health to see that it is alive
- http://localhost:4000/dev/dashboard for the LiveView dashboard

When you save a file in `lib/`, the server restarts and the browser reloads by itself.

Or run Phoenix on your machine and keep only the database in Docker:

```bash
docker compose up -d db
mix setup
mix phx.server
```

Pick one of the two. Both use port 4000, so they cannot run at the same time.

Good to know:

- If you add a package and you run the app in Docker, start it again with `docker compose up --build`.
- Copy `.env.example` to `.env` to change the database settings. Docker Compose reads `.env` automatically. For a local run, export the variables or edit `config/dev.exs`.
- `mix ecto.reset` drops and recreates the database, runs the migrations and the seeds (`MIX_ENV=test mix ecto.reset` if you ever encounter problems with migrations when testing).
- Phoenix builds assets with the `esbuild` and `tailwind` Elixir packages. Node is not necessary.
- Phoenix uses port 4000. If another app already uses it, stop that app or change the port mapping in `docker-compose.yml` and set `PORT` for Phoenix.

## How it was generated

From the `phoenix/` folder:

```bash
mix phx.new hackathon-liveview-starter --app hackathon_liveview --module HackathonLiveView
cd hackathon-liveview-starter
mix phx.gen.live Items Item items name:string
```

The generator printed the routes that are now in `lib/hackathon_liveview_web/router.ex`. The migration is in `priv/repo/migrations/`.

## Where things are

| Path                          | What is in it                                                          |
| ----------------------------- | ---------------------------------------------------------------------- |
| `lib/hackathon_liveview/`     | The domain: contexts, schemas, Repo and Mailer                         |
| `lib/hackathon_liveview_web/` | The web layer: endpoint, router, controllers, LiveViews and components |
| `config/`                     | Configuration for dev, test and prod                                   |
| `priv/repo/migrations/`       | Database migrations                                                    |
| `priv/repo/seeds.exs`         | Seed data                                                              |
| `test/`                       | Context tests, LiveView tests and controller tests                     |

To add your own resource with LiveView, use the generator:

```bash
mix phx.gen.live Blog Post posts title:string body:text
```

Use `mix phx.gen.html` for controllers and HTML views, or `mix phx.gen.json` for a JSON API. Each generator prints the routes to add to the router. Then run `mix ecto.migrate`.

## Scripts

| Command                    | What it does                                             |
| -------------------------- | -------------------------------------------------------- |
| `mix phx.server`           | Run the dev server on port 4000                          |
| `iex -S mix phx.server`    | Run the dev server inside IEx                            |
| `mix setup`                | Install dependencies, create and migrate the database, build assets |
| `mix test`                 | Run the tests                                            |
| `mix precommit`            | Compile with warnings as errors, format and run the tests |
| `mix format`               | Format the code                                          |
| `mix ecto.reset`           | Drop, recreate, migrate and seed the database            |
| `mix ecto.gen.migration`   | Generate a new migration                                 |
